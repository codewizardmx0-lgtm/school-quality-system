# ملاحظات تسلسل العمليات وتدفق الواجهات (Process Flow Observations)

**المشروع:** منصة إدارة وتقويم الجودة المدرسية (`school-eval-api` / `frontend-prototype`)  
**الشرائح المغطاة:** الشريحة 1 (المصادقة والعزل)، الشريحة 2 (التقييم الذاتي والشواهد)، الشريحة 3 (خطط التحسين)  
**تاريخ الإعداد:** 26 أكتوبر 2026

---

## جدول ملاحظات التسلسل والمنطق الإجرائي

| الخطوة | ما لاحظته أثناء الربط والبناء | هل هو منطقي؟ | المصدر المرجعي في الوثائق | اقتراح وتوصية مستقبلية |
|---|---|---|---|---|
| **1. تسجيل الدخول والتوجيه** | يتم تخزين رمز Bearer Token في المتصفح وتحديد دور المستخدم، حيث يوجه المقيم والمدير معاً إلى لوحة ملفات التقييم مع تمييز الصلاحيات. | **منطقي** | `UC-AUTH-01` / `FR-GEN-01..03` | سليم تماماً؛ المقيم والمدير يشاركان في استعراض التقييم، وتختلف صلاحيات الإجراء لاحقاً. |
| **2. اختيار الدورة واستعراض الشجرة** | شجرة المعايير (`standards-tree`) تعيد كلاً من الهيكل الخام ونتائج المدرسة ونسبة الإنجاز دفعة واحدة في طلب واحد، مع إرجاع `resultId: null` للمؤشرات غير المرصودة. | **منطقي جداً** | `UC-SCH-01` / `FR-SCH-02`, `FR-SCH-07` / `SD-01` | يقلل استدعاءات الشبكة ويوفر تجربة سلسة في تحميل استمارة التقييم دفعة واحدة. |
| **3. تعطيل زر إرفاق الشاهد قبل الرصد** | لا يمكن إرفاق شاهد أو تدوين ملاحظة لمؤشر لم يُرصد بعد (`resultId === null`)، حيث يتطلب مسار الشواهد معرّف نتيجة قائمة. | **منطقي** | `BR-SCH-05` / `FR-SCH-10` / `SD-01` الخطوة 7 | تم تطبيق تعطيل الزر في الواجهة مع تلميح توجيهي؛ هذا يحمي الـ API من أخطاء 404 غير الضرورية. |
| **4. رصد التقدير واشتقاق الواصفة** | عند اختيار الدرجة (0-3)، يختار المقيم أدوات التحقق من قائمة الأدوات المعتمدة للمؤشر، ويتم اشتقاق الواصفة المعيارية وحفظ النتيجة فمع تحول المؤشر فورياً إلى `Completed`. | **منطقي** | `FR-SCH-04`, `FR-SCH-05`, `FR-SCH-11`, `FR-SCH-13` / `BR-SCH-05` | يضمن اكتمال التقدير والواصفة فوراً في قاعدة البيانات ويتوافق مع مبدأ الحفظ اللحظي المرن. |
| **5. قفل التقييم عند إغلاق الدورة** | عند محاولة الرصد أو رفع شاهد في دورة مغلقة (`status === 'Closed'`) يرجع الـ API الخطأ 422 مع الرسالة في `errors.cycle`. | **منطقي** | `FR-SCH-01` / `BR-SCH-03` | منع التعديل بعد إغلاق الدورة مع إبقاء القراءة مسموحة يحافظ على سلامة السجلات التاريخية. |
| **6. رفع نسخ الشواهد المتتالية** | الشاهد ينشأ بالنسخة 1، وعند رفع نسخة جديدة يتم تحويل النسخة السابقة تلقائياً إلى غير نشطة وتعيين النسخة الجديدة كـ `current=true` وحيدة. | **منطقي** | `FR-SCH-14b` / `SD-01` الخطوة 10 | تدفق ممتاز يتيح استعراض سجل النسخ التاريخية والتنزيل الآمن دون كشف مسار القرص. |
| **7. الانتقال لاقتراحات التحسين** | اقتراحات التحسين تُحسب ديناميكياً عند الطلب للمؤشرات المرصودة بدرجة أقل من 3، مع تصنيف تلقائي للأولوية (0-1 High و 2 Medium). | **منطقي جداً** | `FR-SCH-16`, `FR-SCH-17` / `SD-02` | يتيح للمقوم معرفة الفجوات فور انتهاء التقييم والانتقال مباشرة للتخطيط دون الحاجة لإدخال يدوي مكرر. |
| **8. تبني الاقتراح كمجال تحسين** | زر «تبني» ينشئ سجلاً في `improvement_areas` مرتبطاً بـ `resultId` للمؤشر، وتتحول علامة التبني إلى `true`، مما يمنع التكرار. | **منطقي** | `UC-SCH-04` / `FR-SCH-16` / قيد العزل المعماري 9 | ربط المجال بـ `resultId` كان حلاً معمارياً حاسماً لضمان العزل المؤسسي ومنع تسريب بيانات المدارس. |
| **9. إنشاء مسودة خطة التحسين** | يشترط النظام اختيار مجال تحسين واحد على الأقل لإنشاء الخطة في جدول `plan_improvement_areas`، وتنشأ الخطة بحالة `Draft` وتقدم `NotStarted`. | **منطقي** | `FR-SCH-19`, `FR-SCH-24` / `SD-02` | يضمن عدم وجود خطط فارغة بلا أهداف واضحة. |
| **10. فرض المفتاح المركب للإجراءات** | عند إضافة إجراء تنفيذي للخطة، يجب اختيار مجال من ضمن المجالات المربوطة بالخطة مسبقاً، وإلا يرفض النظام الطلب بـ 422. | **منطقي صارم** | قيد قاعدة البيانات المركب `(plan_id, area_id)` / `FR-SCH-20` | تم تقييد قائمة مجالات الإجراء بمجالات الخطة الحالية في الواجهة لضمان عدم حدوث خطأ 422 للمستخدم. |
| **11. دورة حياة الخطة (Active / Completed)** | لا يمكن تفعيل الخطة دون وجود مجال وإجراء، ولا يمكن إكمالها إلا بعد إنهاء كافة الإجراءات (`Done` أو `Cancelled`). | **منطقي جداً** | `FR-SCH-24` / `SD-02` | يمنع التحول لحالات تشغيلية وهمية ويفرض الانضباط الإداري. |
| **12. احتساب التأخر ديناميكياً (`isDelayed`)** | حقل `isDelayed` يُحسب برمجياً عند الاستعلام (`due_date < today()`) دون الحاجة لوظائف مجدولة Cron. | **منطقي وعملي** | `FR-SCH-23` / قرار التصميم للشريحة 3 | يبسط البنية التحتية ويعطي المقيم والمدير تنبيهاً مرئياً أحمر فور تجاوز تاريخ الاستحقاق. |
| **13. مراجعة المدير ومنعه من التعديل** | مدير المدرسة يملك مساراً مخصصاً لتدوين الملاحظات (`reviews.write`)، بينما أزرار تعديل الخطة والإجراءات مخفية له ومحمية بـ 403. | **منطقي وحاكم** | `UC-PRIN-01` / `FR-SCH-18` | يجسد الفصل الدقيق بين مسؤولية التنفيذ (للمقيم) ومسؤولية التوجيه والرقابة (للمدير). |
| **14. استمرار عمل الخطة بعد التقييم** | الخطة تظل مفتوحة وقابلة لمتابعة التنفيذ ولا تُقفل بإرسال تقرير التقييم الذاتي. | **منطقي** | `BR-SCH-03` / `FR-SCH-29` | التقييم حدث سنوي نقطي، بينما خطة التحسين مسار تشغيلي مستمر على مدار العام الدراسي. |
