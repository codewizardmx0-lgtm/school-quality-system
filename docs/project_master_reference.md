## 1. فكرة المشروع وأهدافه ونطاقه

### 1.1 الهوية الأكاديمية والجهة الراعية
* **اسم المشروع المعتمد:** نظام تقويم جودة المدارس الوطنية (نظام إدارة الجودة والخطط التعليمية في المدارس / منصة التقييم الذاتي والتحسين المدرسي). ✅
* **طبيعة المشروع:** مشروع تخرج نوعي لنيل درجة البكالوريوس في **هندسة البرمجيات**، قسم علوم الحاسوب، كلية الحاسوب وتقنية المعلومات، جامعة العلوم والتكنولوجيا — الجمهورية اليمنية (العام الجامعي 2026/2027م). ✅
* **المرجعية المعيارية والتشريعية:** الإطار المرجعي الوطني لمعايير الاعتماد المدرسي، الصادر عن قطاع التعليم ومجلس الاعتماد الأكاديمي وضمان جودة التعليم بوزارة التربية والتعليم والبحث العلمي — الجمهورية اليمنية (نسخ وثائق فبراير 2026م). ✅

### 1.2 الفكرة العامة
منظومة سحابية وطنية تفاعلية مركزية تؤتمت عمليات **التقويم الذاتي المؤسسي والاعتماد المدرسي** لمدارس التعليم الأساسي والثانوي. تحل المنظومة محل الإجراءات الورقية المعقدة والمعرضة للتلف والازدواجية، وتوفر آلية تقنية منضبطة لرصد الدرجات وفق سلم رباعي، وربط الأدلة والشواهد، وإدارة وتتبع خطط التحسين المدرسي وإجراءاتها التنفيذية، ورفع المخرجات للإشراف الوزاري، مع تزويد المنظومة بمكوّن **ذكاء اصطناعي مساعد واستشاري** يلتزم بضوابط حوكمة صارمة. ✅

### 1.3 حدود النطاق المعماري (Scoping & Boundaries) ✅
* **التطبيق التجريبي (Pilot Scope):** مقتصر في مرحلته الحالية على مدرستين ممثلتين لمرحلتي الأساسي والثانوي (مدرسة بلقيس الثانوية للبنات بأمانة العاصمة، ومدرسة الفاروق الأساسية للبنين بتعز).
* **التقييم الذاتي الداخلي مقابل الاعتماد الخارجي:** المنظومة مخصصة **للتقويم الذاتي والتحسين المدرسي الداخلي والمتابعة الوزارية**؛ النظام **لا** يمنح شهادات اعتماد رسمي خارجي ولا يصدر قرارات اعتماد قانونية، والمراجعة الوزارية ليست اعتماداً خارجياً (قاعدة العمل `BR-MIN-03`).
* **استقلالية المنظومة:** لا يوجد تكامل تقني مباشر مع منظومات وزارية خارجية (مثل إدارة الاختبارات العامة أو الرواتب أو شؤون المعلمين المالية)؛ المنظومة معنية بحوكمة وضمان الجودة والخطط التطويرية حصراً.
* **موقع الذكاء الاصطناعي:** مكوّن استشاري مساعد (Advisor Only)، محظور عليه تعديل أي درجة أو شاهد أو بيان رسمي، وتخضع مقترحاته للمراجعة والموافقة البشرية الإلزامية (`BR-AI-01` و `BR-AI-02`).

## 5. القرارات المعمارية المعتمدة وأسبابها (Architectural Decisions - ADRs) ✅

هذه القرارات **حاسمة ومجمدة**؛ لا يجوز لأي نموذج إعادة نقاشها أو نقضها:

1. **فصل الواجهة الأمامية عن الـ API بالكامل:** واجهة React منفصلة تتواصل عبر HTTPS/HTTP مع Laravel API بصيغة JSON حصراً.
2. **مصادقة Bearer Tokens عبر Laravel Sanctum:** إصدار الرمز وحفظه في `sessionStorage` بالمتصفح، وإرساله في ترويسة `Authorization: Bearer <token>`، وتخزين الرموز بجدول `personal_access_tokens` التشغيلي المنفصل عن الجداول الـ 40.
3. **قاعدة التبعية المؤسسية الحصرية (XOR Constraint):** الحساب يرتبط بمدرسة (`school_id`) أو بجهة وزارية (`ministry_id`) ولا يجوز الجمع بينهما إطلاقاً؛ ويكونان فارغين فقط لمسؤول النظام (`user_type = system`).
4. **سياسة «تعطيل لا حذف» (Disable Not Delete):** محظور حذف المدارس أو المستخدمين أو المعايير أو التقييمات بحذف فيزيائي نهائي؛ التعديل يتم بتحويل الحالة (`Active` / `Inactive` أو `Disabled`) حمايةً للتكامل المرجعي وسجلات الجودة.
5. **قاعدة إخفاء الموارد المعزولة برمز 404 بدلاً من 403:** إذا طلب مستخدم مدرسة مورداً يخص مدرسة أخرى (تقييم، شاهد، مدرسة)، يعيد الخادم فوراً `404 Not Found` برسالة «العنصر المطلوب غير موجود» بدلاً من `403` لحجب وجود المعرف ومنع استكشاف الموارد (القرار 9).
6. **فرض إنهاء الجلسة بعد 30 دقيقة خمول:** وسيط برمجي (`session.timeout`) يفحص آخر نشاط للمستخدم ويحدث جدول `sessions` الوظيفي (FR-GEN-02) ويلغي صلاحية الرمز عند تجاوز المدة.
7. **المغلف الموحد لاستجابات JSON:** تعود كافة الردود بمغلف ثابت:  
   `{ "data": ..., "message": "...", "errors": ..., "meta": ... }`  
   مع اعتماد `camelCase` لحقول الـ JSON مقابل `snake_case` في قاعدة البيانات.
8. **تجزئة كلمات المرور عبر عمود `password_hash`:** كلمة المرور تشفر بخوارزمية Bcrypt ولا تُخزن كنص صريح إطلاقاً، والنموذج يخصص دالة `getAuthPasswordName()`.
9. **حظر كلمات المرور الصلبة:** قراءة كلمة المرور الافتراضية للتطوير من ملفات البيئة (`SEED_DEFAULT_PASSWORD` بالـ API و `VITE_DEV_DEFAULT_PASSWORD` بالواجهة)، وإخفاء أزرار التعبئة التجريبية في بيئة الإنتاج عبر `{import.meta.env.DEV && (...)}`.
10. **حوكمة واستقلالية الذكاء الاصطناعي:** الذكاء الاصطناعي مكوّن مساعد واستشاري فقط، يُعزل في طابور مهام خلفية (Queue Job)، ومخرجاته تنزل بحالة `PendingReview` ولا تدرج في أي خطة تحسين إلا بقرار واعتماد بشري صريح.

## 9. المشاكل السابقة وكيف تم حلها وتلافيها (Troubleshooting Log) ⚠️

1. **خطأ ParseError في تسجيل الدخول (syntax error, unexpected `@`):**
   - **السبب:** تسرب الرمز `@var` خطأً داخل دالة `forgetUser()` في `AuthController.php`.
   - **الحل:** تم تصحيح السطر والتأكد عبر `php -l`. **القاعدة:** يجب دائماً التحقق من سلامة البنية النحوية للـ PHP بعد أي تعديل.
2. **خطأ انقطاع الاتصال بقاعدة البيانات (SQLSTATE 2002 Connection Refused):**
   - **السبب:** توقف خدمة MySQL أو عدم بدء تشغيل `mysqld.exe`.
   - **الحل:** تشغيل الخدمة عبر Laragon أو أمر PowerShell، وتوثيق أوامر التشغيل في دليل `كيفية_التشغيل.md`.
3. **تسرب كلمات المرور الصلبة في الكود (Hardcoded Passwords):**
   - **السبب:** وضع كلمة المرور صراحة في كود `LoginPage.tsx`.
   - **الحل:** نقلها فوراً إلى متغير البيئة `VITE_DEV_DEFAULT_PASSWORD` وتغليف أزرار الحسابات التجريبية بالشرط `{import.meta.env.DEV && (...)}` لحجبها تلقائياً في الإنتاج.
4. **تلف الحروف العربية في شواهد المعايير:**
   - **السبب:** استخدام دوال تقطيع النصوص العادية التي تفصل البايتات.
   - **الحل:** الاعتماد على دوال الـ Multibyte (`mb_*`) وتخزين الشواهد كمصفوفات نظيفة، مما قلص الشواهد المشوهة من 958 إلى 278 شاهداً سليماً مطابقاً للوثيقة الرسمية.

## 11. محددات وضوابط صارمة للنموذج المساعد الجديد ⚠️

> [!CAUTION]
> **ممنوعات هندسية ومعمارية قطعية:**
> 1. **ممنوع تشغيل أمر `migrate:fresh` نهائياً** أو مسح قاعدة البيانات؛ فالقاعدة محقونة بكامل المعايير والمدارس والمستخدمين والتقييمات المعتمدة.
> 2. **ممنوع تعديل هيكل الجداول الـ 40 الأساسية**، أو تغيير مفاتيحها أو أسماء أعمدتها الموثقة في قاموس البيانات.
> 3. **ممنوع استخدام الحذف الفيزيائي (`DELETE`)** في المدارس أو الحسابات أو المعايير أو التقييمات؛ استخدم التعطيل (`Active` / `Inactive` أو `Disabled`).
> 4. **ممنوع خرق العزل المؤسسي؛** أي استعلام عن مدرسة أخرى من حساب مدرسي يجب أن يعيد **404 Not Found** وليس 403.
> 5. **ممنوع استخدام ألوان أو مسافات صلبة خارج `src/styles/theme.ts`**؛ استخدم دائماً ثوابت نظام التصميم المعتمد.
> 6. **حافظ على قاعدة التسمية:** أسماء الأعمدة في قاعدة البيانات `snake_case`، وتحول في استجابات الـ API إلى `camelCase`.
