### التعديل 2: تصحيح صيغة التواريخ في استجابات الـ API
* **الموقع:** القسم 4.4.1 (أمثلة استجابات JSON في السطور 224 و233).
* **النص قبل التعديل:**
  ```json
  "updatedAt": "2026-10-12T09:41:00+03:00"
  ...
  "submittedAt": "2026-10-10T11:20:00+03:00"
  ```
* **النص بعد التعديل:**
  ```json
  "updatedAt": "2026-10-12T06:41:00Z"
  ...
  "submittedAt": "2026-10-10T08:20:00Z"
  ```
  مع إضافة التوضيح المعماري:
  > تُرسل التواريخ في استجابات الـ API بصيغة UTC منتهية بـ Z، ويقوم تطبيق React بتحويلها إلى التوقيت المحلي (+03:00) عند العرض فقط.
* **السبب:** إزالة التعارض مع القسم 6 في وثيقة الاتفاقيات conventions.md الملزم بإرسال التواريخ بصيغة UTC المنتهية بـ Z حصراً.

### التعديل 9: إضافة نموذج الخطأ 403 وحسم سلوك الخطأ 404

* **النص بعد التعديل:**
  - إضافة نموذج استجابة الخطأ 403 بصيغة JSON الموحدة:

    ```json
      "errors": null,
      "meta": null
    }
    ```
  - استبدال السطر 261 بما يلي:
    `يُرجع 404 عند طلب مورد يخص مدرسة أخرى، لمنع كشف وجوده، مع بقاء 403 للحالات التي يُعرف فيها المورد ويُمنع الوصول إليه. [قرار]`
* **السبب:** توثيق الاستجابات الأمنية المعتمدة لحماية سرية المدارس وفق معايير الأمان المعتمدة.

### التعديل 10: توثيق التعارض المعماري في المتطلب FR-SUP-16
* **الموقع:** القسم 4.4.4 (بعد جدول كتالوج نقاط النهاية).
* **الإجراء المطبق:** إضافة تنبيه معماري رسمي بنص:
  > يوجد تعارض معماري موروث من التحليل: FR-SUP-16 ينص على ربط ملاحظات المشرف بمدرسة أو مخرج أو طلب استكمال، بينما جدول القاموس يحصر الربط في المخرج (`submission_id`). يُعتمد جدول القاموس في هذا التصميم، ويُسجّل التعارض ليُحسم في مرحلة التنفيذ.
* **السبب:** الشفافية الهندسية وتوثيق التعارض الموروث من التحليل وتحديد المرجع الحاكم المعتمد حالياً.

### التعديل 12: استيفاء قيم المتطلبات غير الوظيفية
* **الموقع:** القسم 4.10.1 (جدول المتطلبات غير الوظيفية).
* **النص قبل التعديل:**
  وسوم `[املأ]` في خانات وسيلة التحقق للأداء والموثوقية والاستخدام والتوافقية والتتبع.
* **النص بعد التعديل:**
  - الأداء: زمن استجابة أقل من ثانيتين لـ 95% من الطلبات.
  - الموثوقية والتوافر: قيمة غير محددة في الفصل الثالث.
  - قابلية الاستخدام: واجهة عربية RTL، قوائم بحسب الدور، رسائل خطأ واضحة، مع اختبارات قبول المستخدم (UAT).
  - التوافقية: دعم المتصفحات الحديثة: Chrome وEdge وFirefox وSafari.
  - التتبع والإشعارات: جدول `notifications` دائم، وإشعارات الأحداث الخمسة، ويُختبر في مرحلة بناء الخدمات.
* **السبب:** نقل القيم المستهدفة المعتمدة من الفصل الثالث وتوضيح وسيلة قياسها.

### التعديل 14: حسم القرارات المعمارية المفتوحة
* **المواقع:** الأقسام 4.5.1، 4.5.6، 4.7.5، 4.8، 4.9.4.
* **القرارات المطبقة:**
  1. **فرض الخمول (4.5.1):** اعتماد فحص وتحديث حقل النشاط في جدول `sessions` الوظيفي عبر Middleware، وإلغاء الرمز عند تجاوز مدة الخمول (30 دقيقة) كقرار `[قرار]`.
  2. **تخزين الرمز في المتصفح (4.9.4):** اعتماد التخزين في `sessionStorage` للجلسة الواحدة لتعزيز الأمان عند إغلاق التبويب كقرار `[قرار]`.
  3. **قنوات الإشعارات (4.7.5):** الاكتفاء بسجل الإشعارات الداخلي الدائم في جدول `notifications` وتأجيل النسخة البريدية لما بعد المرحلة التجريبية كقرار `[قرار]`.
  4. **سجل التدقيق Audit Log (4.5.6):** الاكتفاء بالهيكل الحالي (طوابع التحديث، الجلسات، الإشعارات، وسجلات الملاحظات) دون جدول تدقيق منفصل في المرحلة التجريبية كقرار `[قرار]`.
  5. **إدارة الحالة في الواجهة (4.9.4):** اعتماد `TanStack Query` (`React Query`) لإدارة بيانات الخادم والتخزين المؤقت مع `Context API` لحالة التطبيق العامة كقرار `[قرار]`.
  6. **مكون الذكاء الاصطناعي ومزوده الخارجي (4.8):** تثبيت المكون الحالي كنموذج Mock، وتجريد الخدمة خلف واجهة `AiAnalysisServiceInterface`، وتأجيل المزوّد الخارجي الحقيقي للأعمال المستقبلية كقرارين معتمدين `[قرار]`.
* **السبب:** إغلاق كافة التساؤلات المعمارية المفتوحة وتثبيت قرارات التصميم والتنفيذ.

## 3. التحقق الأمني والرقابي على التعديلات

1. **الالتزام بالقواعد الصارمة:** لم يتم تعديل أي ملف في المستودع خارج ملف الفصل الرابع [`docs/chapter4/chapter4_system_design.md`](file:///c:/laragon/www/school-quality-system/docs/chapter4/chapter4_system_design.md) وهذا التقرير.
2. **الحفاظ على المعمارية المعتمدة:**
   - واجهة React منفصلة + Laravel API.
   - Bearer Tokens عبر Laravel Sanctum.
   - MySQL 8.4 مع 40 جدولاً.
   - RBAC بـ 5 أدوار و19 صلاحية.
   - سياسة التعطيل بدلاً من الحذف الفيزيائي للحسابات.
   - حوكمة الذكاء الاصطناعي وإبقاء دوره استشارياً تحت إشراف بشري تام.
