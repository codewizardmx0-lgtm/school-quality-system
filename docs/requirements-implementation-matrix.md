# مصفوفة مطابقة المتطلبات وحالات الاستخدام مع التنفيذ الفعلي (مُهيكلة حسب الفاعلين)
## Requirements & Use Cases Traceability Matrix by Actor (RTM)

> **المشروع:** نظام إدارة الجودة والتقويم والاعتماد المدرسي (`school-quality-system`)  
> **الهيكلة:** مُقسّمة حرفيًا حسب الفاعلين (Actors) تطابقًا تامًا مع وثيقة متطلبات النظام المعتمدة (SRS - النسخة النهائية كامل 5.pdf).  
> **حالة الوثيقة:** وثيقة مرجعية حية (Living Document) تُحدّث دورياً بعد كل مرحلة.  
> **تاريخ التحديث:** 7 نوفمبر 2026م.  
> **الفرع الحالي:** `feature/school-evaluator-ui`.  

---

## 1. قواعد وضوابط إدارة الوثيقة الحية

1. **الالتزام بتقسيم الفاعلين (Actors):** لا يُبتكر أي تقسيم أو تصنيف مغاير؛ كل متطلب وحالة استخدام تُدرج تحت الفاعل المعني به في وثيقة SRS.
2. **التحديث الإلزامي:** يُحدّث هذا الملف فور إنجاز أي دفعة وظيفية، مع بيان رقم الـ Commit والملفات المتأثرة.
3. **المزامنة الثلاثية:** يُقيّم كل متطلب وحالة استخدام عبر 3 زوايا:
   - حالة الباك إند (Backend API).
   - حالة واجهات React المعتمدة (`school-eval-web`).
   - حالة النموذج المبدئي التاريخي (`frontend-prototype`).
4. **التطابق الصارم مع الكود:** لا يُكتب "منجز" إلا لمتطلب مغطى باختبار آلي ناجح وواجهة مستخدم تعمل بدون أخطاء.
